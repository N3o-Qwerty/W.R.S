Dark

Hack Smarter · Linux · An outdated WordPress site hands over an admin account; from there a custom plugin runs code as the web user, and a credential left in a readable log finishes the job.

A Hack Smarter lab, shared with permission. Credentials and flag values are redacted — the point is the method, not the answers.

1. Recon

Only SSH and HTTP are open. Port 80 is a WordPress 6.0 site (well out of date). Scan it with WPScan and corroborate with Nuclei.

nmap -p- -sC -sV -oA scans/all TARGET
wpscan --url http://TARGET --enumerate p,u --plugins-detection mixed
nuclei -u http://TARGET -tags wordpress

WordPress 6.0 carries a long list of known issues, the usual endpoints are exposed (xmlrpc.php, wp-cron.php, a readable wp-content/debug.log), and user enumeration via the REST API and author feeds reveals the administrator account.

curl http://TARGET/wp-json/wp/v2/users/   # ["adminuser"]

2. Into wp-admin

With the administrator's username known, authenticate to wp-admin — on this box through a WordPress password attack against that account (WPScan can drive it through xmlrpc.php, which is enabled).

wpscan --url http://TARGET --usernames adminuser \
  --passwords /usr/share/wordlists/rockyou.txt

Admin access to WordPress is effectively code execution waiting to happen, because an administrator can install plugins.

3. A Malicious Plugin

Rather than a noisy public shell, package a small plugin whose admin page opens a connection back to you and runs whatever you send. Zip it, upload it under Plugins → Add New → Upload, activate it, and open its page.

# system-health-monitor.php — plugin header + an admin page that
# connects to YOUR_IP:1337 and pipes input to shell_exec()
# (set your host/port, zip, upload, activate, open the page)
nc -lvnp 1337     # catch the callback

The callback arrives as www-data. Upgrade to a proper TTY and start local enumeration.

4. Privilege Escalation

From www-data, the quickest wins are usually the WordPress database config and the logs. Here the path runs through a readable file under /var/log: a credential recorded in a log the web user can read, which is reused for a higher-privileged account and leads to root.

cat /var/www/html/wp-config.php      # DB creds to try first
grep -ri pass /var/log 2>/dev/null   # credentials left in logs
sudo -l                              # check once you have a user

Reuse the recovered credential to escalate, and the root flag follows.

What To Take Away

  • Keep WordPress current and disable xmlrpc.php — it enables quiet password attacks and user enumeration.
  • An admin who can upload plugins can run code. Protect admin accounts with strong, unique passwords and MFA.
  • Secrets in world-readable logs are a classic escalation. Keep credentials out of logs and restrict log permissions.
  • Check wp-config.php and /var/log first after a web foothold.
