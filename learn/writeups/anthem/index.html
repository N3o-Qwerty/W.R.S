Anthem

TryHackMe · Windows · Easy. No brute forcing — just careful reading. An Umbraco blog, a password left in robots.txt, RDP access, and a hidden file that owns the box.

Targets and flag values are from a shared practice environment and are redacted here. The point is the method, not the answers.

1. Recon

The host does not answer ping, so a default scan reports it as down. Skip host discovery with -Pn and scan anyway.

nmap -Pn -p- --min-rate 1000 -oA scans/all-ports TARGET
nmap -Pn -p 80,3389 -sC -sV -oA scans/services TARGET
  • 80/tcp — HTTP. An Umbraco CMS blog (the Articulate theme).
  • 3389/tcp — RDP. Remote Desktop, which will matter once we have credentials.

Lesson one of the room: a “host down” result often just means ICMP is filtered. Always confirm with -Pn.

2. Reading the Blog

This room rewards slow reading. The flags and clues are scattered through the site itself.

gobuster dir -u http://TARGET -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt

What the pages give up

  • Flags in the source. Several flags are tucked into HTML comments, a search placeholder, and author pages — view-source is your friend.
  • A name and an email pattern. Posts and author pages reveal the admin's full name and the company email format (first initial / name @ the domain).
  • A poem about the admin. A blog post written in his honour is a strong hint about where the password lives.

3. The Password in robots.txt

Always check robots.txt. Besides the usual Disallow rules for the Umbraco directories, there is a stray line that is clearly a password left in the open.

curl http://TARGET/robots.txt

Combine that password with the admin's email (worked out from the blog) and log in to Umbraco at /umbraco. The CMS panel itself has nothing useful — but the same credentials are what matter next.

4. Foothold over RDP

The admin reused that password for his Windows account, so the web credentials get us an interactive desktop over RDP.

xfreerdp /u:USER /p:PASS /v:TARGET /dynamic-resolution

The user flag is sitting on the desktop.

5. Privilege Escalation

The administrator password is stashed in a hidden file on the system drive. List hidden files to find it.

dir /a:h C:\

The file cannot be read from the command line as our user, but we own it — so we open its properties in Explorer, take ownership, grant ourselves read, and open it. Inside is the administrator password.

Logging in as Administrator with that password gives full control, and the root flag follows.

Why it worked

“Hidden” is not a permission. A hidden file you own is still yours to re-permission, and secrets stored in a file on disk are only as safe as the file's ACL.

What To Take Away

  • A filtered ping is not a dead host. Confirm with -Pn.
  • Read the content and the page source. Half of this room is hidden in plain sight.
  • Check robots.txt every time.
  • One password reused across the CMS, RDP, and a stored file is what chains the whole box together.
