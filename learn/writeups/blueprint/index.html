Blueprint

TryHackMe · Windows · Easy. An old XAMPP host runs a shopping-cart app with its installer still exposed. Because the web stack runs as SYSTEM, one request turns into full control.

Targets and flag values are from a shared practice environment and are redacted here. The point is the method, not the answers.

1. Recon

Scan everything, then fingerprint each service.

nmap -p- --min-rate 1000 -oA scans/all-ports TARGET
nmap -p 80,135,139,443,445,3306,8080 -sC -sV -oA scans/services TARGET
  • 80/tcp — Microsoft IIS 7.5 (an empty 404 site).
  • 443 & 8080/tcp — Apache 2.4.23 with PHP 5.6.28. That is the signature of an old XAMPP install, and both serve open directory listings.
  • 445/tcp — SMB on Windows 7 Home Basic SP1, signing disabled.
  • 3306/tcp — MariaDB.

An unpatched Windows 7 box running an ageing XAMPP stack is a strong lead. The directory listing on 8080 is where to look next.

2. Finding the Application

Browsing the listing on 8080 reveals an osCommerce 2.3.4 shop. Two quick checks matter: the version, and whether the install/ directory is still reachable.

curl http://TARGET:8080/oscommerce-2.3.4/catalog/install/install.php

It is. A live installer on a production app is a classic finding on its own — it often allows re-configuration, and in this version it allows code execution.

A quick look at SMB confirms guest access is open, which is worth noting even though we will not need it.

nxc smb TARGET
smbclient -N //TARGET/Users

3. Installer RCE

osCommerce 2.3.4 has a known remote code execution flaw: when the installer is still present, the install.php?step=4 flow can be abused to inject system commands (Exploit-DB 50128). Point the public proof of concept at the exposed installer.

searchsploit -m 50128
python3 50128.py http://TARGET:8080/oscommerce-2.3.4/catalog/install/install.php?step=4

That drops into a command shell on the host.

4. Already SYSTEM

Check who the shell runs as before reaching for any privilege escalation.

whoami
# nt authority\system

There is nothing to escalate. On this host XAMPP's Apache runs as LocalSystem, so code execution through the web app is already the highest privilege on the machine. Both the user and root flags are readable directly.

While looting, a passwords.txt left by XAMPP lists its default credentials (phpMyAdmin with a blank root password, the default WebDAV account, and so on) — a reminder of how much a default install leaves lying around.

What To Take Away

  • Delete installers once setup is done. A live installer is a standing invitation.
  • Do not run a web server as SYSTEM. If the stack had dropped privileges, this would have been a low-privilege shell, not game over.
  • Old bundled stacks (XAMPP, legacy PHP) carry known CVEs. Match the version to public exploits early.
  • Open directory listings and guest SMB shares hand an attacker a map for free.
