Build a Home Lab

The fastest way to improve is to have somewhere you are allowed to break things. A small, isolated lab on one computer is enough to practise nearly everything in the learning path.

Keep your lab isolated from your home network and the internet. Only ever attack machines inside it, or targets you have written permission to test.

Why Build One

Online platforms are great for guided practice, but a local lab lets you work offline, break and rebuild targets freely, keep intentionally vulnerable machines you would never expose to the internet, and test tools and payloads without a timer or a connection. It is also the only way to practise some attacks — building your own small Active Directory, for example — end to end.

The Build

  1. Pick a hypervisor

    Software that runs virtual machines. On a laptop or desktop, VirtualBox (free) or VMware Workstation/Fusion is plenty. If you have a spare machine to dedicate, Proxmox gives you a always-on lab you reach over the network. Any one of them works — start with what installs easily.

  2. Build an attacker VM

    Install Kali or Parrot as your attack box and take a snapshot once it is set up and updated. This is where your tools live — scanners, a proxy, wordlists — so you never test from your host machine.

  3. Put it on an isolated network

    Give the lab its own virtual network (host-only, or an internal network) so the vulnerable machines cannot reach your home LAN or the internet. Vulnerable VMs are, by design, easy to compromise — they must never be exposed. Add internet only to the attacker VM, and only when you need it.

  4. Add vulnerable targets

    Download ready-made vulnerable machines (see below) and import them onto the isolated network. Mix Linux and Windows, web apps and services, so you practise the full enumeration-to-root loop against different stacks.

  5. Snapshot everything

    Snapshot each VM in a clean state before you attack it. When you break a box — and you will — roll back in seconds instead of rebuilding. Snapshot the attacker VM before big changes too.

  6. Grow into a mini Active Directory

    When you are ready for Windows and AD, stand up a Windows Server evaluation as a domain controller with one or two client VMs joined to it. It is the best way to practise the enumeration, credential, and escalation chains from the AD write-ups safely.

Keep It Sane

  • Isolation first. Confirm a target cannot ping your router or the internet before you attack it.
  • Mind resources. Run only the VMs you need. 2–4 GB RAM per target and a couple of cores is usually enough; start small.
  • Snapshot before, not after. A clean baseline is what makes a lab reusable.
  • Take notes here too. Treat lab boxes like real targets — log commands and findings as you go.
  • Throw boxes away. Delete and re-import freely. Nothing in the lab is precious.
  • Stay in scope. The lab is your scope. Do not point lab tooling at anything outside it.
